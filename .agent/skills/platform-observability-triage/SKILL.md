# Platform Skill: Observability Stack Diagnostics & Triage

## Overview
This skill equips an autonomous AI agent or platform engineer with diagnostic workflows to triage latency, missing traces, memory exhaustion (OOM), and telemetry pipeline failures across the Grafana LGTM stack (`alloy`, `loki`, `tempo`, `prometheus`, `grafana`) on AWS EC2 `t2.micro`.

---

## 1. High-Priority Diagnostic Workflows

### Scenario A: Missing Traces in Grafana / Tempo Gateway Timeout (HTTP 504)
When Grafana's "OpenTelemetry Distributed Traces" panel is spinning or returns `HTTP 504`:

1. **Check Linux Kernel Cgroup OOM Kills:**
   ```bash
   dmesg -T | grep -i oom
   ```
   *Action:* If `tempo` was terminated by the OOM killer, verify that `mem_limit` in `docker-compose.yml` is at least `140m` and Go runtime is set to `GOMEMLIMIT=95MiB` with `GOGC=25`.
2. **Verify Tempo Internal gRPC Port Binding (`9095`):**
   ```bash
   sudo docker logs --tail 50 tempo | grep -E "adding connection|9095"
   ```
   *Action:* Tempo's internal querier must establish a connection to `127.0.0.1:9095`. If missing, verify `grpc_listen_port: 9095` is declared under `server:` in `tempo-config.yml`.
3. **Verify Nginx Reverse Proxy Read Timeout:**
   *Action:* TraceQL multi-block compaction searches take up to 25s under CPU throttling. Ensure `proxy_read_timeout 120s;` is configured in `/etc/nginx/conf.d/default.conf`.
4. **Direct In-Container Trace Search Query:**
   ```bash
   curl -s -k "https://127.0.0.1/grafana/api/datasources/proxy/uid/tempo/api/search?limit=5"
   ```

---

### Scenario B: High CPU Steal (`%st`) on `t2.micro`
AWS `t2.micro` instances operate on CPU burst credits (6 credits/hour). Depleting credits causes CPU throttling:

```bash
# Check CPU Steal and I/O Wait (Look at 'st' and 'wa' columns)
vmstat 1 5

# Check per-process CPU consumption
top -b -n 1 | head -n 20
```
*Triage Action:* If `%st` is above 50%, pause non-essential background tasks, avoid running heavy container builds or parallel package installations on the host, and allow the CPU credit balance to accumulate.

---

### Scenario C: Correlated Logs-to-Traces Broken in Loki
1. **Check Nginx Edge Log Ingestion in Loki:**
   ```bash
   curl -s "http://127.0.0.1:3100/loki/api/v1/query?query=%7Bapp%3D%22nginx%22%7D" | grep -q "trace_id"
   ```
2. **Validate Grafana Loki Derived Field Configuration:**
   Inspect `docker/lgtm/grafana/provisioning/datasources/datasources.yml`:
   ```yaml
   derivedFields:
     - name: TraceID
       matcherRegex: '"trace_id":"([a-f0-9]+)"'
       url: "$${__value.raw}"
       datasourceUid: tempo
   ```
3. **Verify Alloy Pipeline Status:**
   ```bash
   curl -s http://127.0.0.1:12345/metrics | grep alloy_component
   ```

## 2. Resource Sizing & Memory Governance Thresholds

| Service | Docker `mem_limit` | `GOMEMLIMIT` | Key Memory Triage Check |
| :--- | :---: | :---: | :--- |
| **tempo** | `140m` | `95MiB` | Ensure Parquet block compaction is enabled; disable in-memory span metrics generator |
| **grafana** | `128m` | `75MiB` | Verify anonymous viewer mode (`GF_AUTH_ANONYMOUS_ENABLED=true`) |
| **prometheus** | `112m` | `70MiB` | Verify `--storage.tsdb.retention.size=256MB` |
| **loki** | `96m` | `60MiB` | Verify TSDB v13 schema and filesystem storage |
| **alloy** | `80m` | `55MiB` | Verify direct in-memory routing to Loki (`:3100`) and Tempo (`:4317`) |

## 3. Live End-to-End Tracing Verification Script

Execute the following commands to generate synthetic traffic and confirm trace generation:

```bash
# 1. Trigger synthetic HTTP request
curl -k -s "https://127.0.0.1/" > /dev/null

# 2. Wait 3 seconds for FastCGI shutdown and Alloy batch flush
sleep 3

# 3. Query Tempo for latest traces generated by nginx-edge-proxy
curl -s -k "https://127.0.0.1/grafana/api/datasources/proxy/uid/tempo/api/search?limit=1" | \
  grep -o '"traceID":"[a-f0-9]*"' | head -n 1
```
